## 二、规则框架缺口

后续卡牌描述格式都依赖这些底层能力，应先于大规模卡牌重写完成。

1. **自动能力触发框架 (8.5)**：所有「……时」统一发出事件 (出场、攻击、被破坏、离场、回合开始/结束、充能、受到伤害等)；满足条件的【自】能力进入待处理池 (`pendingTriggers` 目前未使用)，在检查时机按「回合玩家优先、同一玩家自选顺序」处理；处理中再次触发、来源卡已离场、【回合1】等次数限制都要按规则处理。目前只有奥兹玛与可靠的伙伴两个触发直接写在调用处。
2. **统一的持续效果层 (8.9)**：所有 PP/DP 增减、词条的获得与失去、费用增减都表示为「来源 + 作用范围 + 期限」并按规则顺序计算；区分「此时符合条件的角色」(锁定对象，如暗域力场) 与「符合条件的所有角色」(持续判定，如【永】)。把残留的 `tempPPBonus`、`tempDPBonus`、`grantedKeywords` 迁移到 `CardModifier`，修正效果赋予的词条不会到期的问题 (如 BP01-002 的【突进】)。
3. **替代效果与禁止效果**：「代替……」「不能……」「视为……」(如 BP04-032 炽能球视为【红色信号球】) 在对应行动执行前插入判断。
4. **未实现的机制**：协战、浮空、角色与装备上的【瞬时】能力 (目前只检查手牌中的瞬时战术牌)、带条件或代价的【充能自】(BP03/BP04 的部分卡牌，目前不发动)。
5. **玩家自选代价**：支付费用时选择横置哪些明费、使用哪些暗费 (目前固定先明费后暗费)，以及丢弃、消除的对象统一做成玩家决策。
6. **升变**：BP01-040、BP04-061 的升变条件尚无法解析，目前拒绝升变。

## 三、卡牌效果：效果原语 + 声明式卡牌描述

逐卡手写代码 (`effects/preset-cards.ts`) 只适合作为过渡。目标是引擎提供效果原语，每张卡是一段由引擎解释执行的描述，新卡包上线主要是写数据：

```ts
'ST01-010': [
  公开牌组顶(5),
  选择({ 范围: '公开的牌', 条件: { 特征: '灰鸦小队', 类型: '角色' }, 数量: 1 }, 加入手牌),
  其余放置到牌组底(),
]
```

1. 从 `preset-cards.ts` 提炼正式的原语：公开、选择 (范围、条件、数量、必选/可选)、区域移动、数值修改、代价 (丢弃、消除信号球、横置、支付费用)、条件判断、「若如此做」、「那之后」、持续效果。
2. 定义带类型校验的描述格式，描述写错时直接报错，不能静默执行错误效果。
3. 先把预组 42 张改写为描述，用现有 `test/preset-cards.test.ts` 保证行为不变。
4. 统计 490 张卡需要的原语并补齐；机制特殊的卡 (如 BP03 的《里·超刻》系列) 允许以单独代码实现作为例外。
5. 按卡包逐包转换：先用程序从卡牌文本生成描述草稿，再人工对照卡面校对；每包 1~2 个 PR。
6. 全部转换完成之前，**对尚未精确实现的卡牌在前端给出明确标记** (审查报告整改计划第 4 项，尚未完成)，而不是让玩家以为近似效果就是正确效果。

## 四、验证体系

测试目前只能证明「代码符合实现者对规则的理解」，需要补充能发现理解偏差与流程问题的手段：

1. **条款覆盖**：规则整理中的每条条款至少对应一个测试，测试名标注条款编号，可以统计未覆盖的条款。
2. **官方 Q&A 用例化**：规则整理 §11 的逐卡 Q&A 每条转为一个测试；官方发布新 Q&A 时同步补充。
3. **随机对局压测**：程序随机对战大量对局，检查不变量 —— 卡牌总数守恒、不出现非法状态、流程不会卡死、失败行动不留修改、快照可完整恢复。
4. **回放回归**：真实对局的行动序列保存为用例，引擎改动后重放比对结果。
5. **隐藏信息检查**：自动检查任何决策提示、事件与脱敏状态都不包含对手手牌、牌组顺序与暗费。
6. **实战校对**：请熟悉实战的玩家按官方 Q&A 对照打几局，重点是同时触发、时机交错等边界情况。

## 六、前端视觉重构

依据 [前端设计规范](design/design-spec.md)，把现有霓虹青、圆角、任意像素值混用的界面统一为官方风格 (黑白为主、绯红点缀、直角细线、HUD 装饰)。现有用量：`terminalCyan` 821 处、`rounded-*` 549 处、`text-[Npx]` 337 处、`font-mono` 535 处、霓虹 `shadow-[...]` 108 处。

每一步一个 PR，合并后两种部署方式都必须可用：

- [x] 设计规范 (`docs/design/design-spec.md`)
- [x] 设计 Token 与自托管字体：新旧 Token 并存，外观不变
- [ ] 基础组件 `src/components/ui/`：Button、Panel、SectionHeader、Tabs、Input、Dialog、Badge 与 HUD 装饰件，补渲染冒烟测试
- [ ] 外围页面迁移：首页、登录、大厅、等待室、卡库、卡组、历史、回放、指南、管理后台 (可按页面拆成多个 PR)
- [ ] 对局页迁移：`GameClient.tsx` 与 `components/game/*`，按规范第 6 节调整卡牌状态、阶段横幅与侵蚀条；两种部署方式各实际打一局
- [ ] 清理：删除旧 Token 与 `.terminal-*`、`.corner-*` 等旧样式，可选在 lint 中禁止任意值字号与裸色值

待定事项：

- 信号球三色 (`orb-*`) 是暂定值，需对照卡图取样校正，并为色弱用户加形状或字母标记。
- 对局页在竖屏手机上的布局 (规范目前只要求提示横屏)。
