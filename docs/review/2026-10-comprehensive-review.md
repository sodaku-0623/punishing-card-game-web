# 全面审查报告 (2026-10)

审查范围：交互、样式、功能、体验、性能、安全与项目管理。
审查基线：`dda469c`（main）。下表中「已修复」项均包含在本次 PR 中，「建议」项未在本次 PR 中改动。

验证方式：

- `npm run build` / `npm run lint` / `npm run typecheck` / `npm test` 全部通过（引擎 55、服务端 35、规则 6、数据库 4、前端 4）。
- 浏览器双会话冒烟测试（Playwright）：游客 A 创建带密码房间 → 游客 B 进入时弹出密码框 → 错误密码被拒 → 正确密码加入 → 双方准备 → 开局进入对局桌面，连续 4 次通过且无页面/控制台错误。

## 一、功能与安全

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| 严重 | Socket 身份完全由客户端自报：`room:join`、`game:reconnect` 负载中的 `userId` 可任意填写，任何人都能以他人身份重连对局并读取对方手牌等隐藏信息。 | 已修复：握手中间件统一确定身份（JWT 优先，游客不得冒用注册账号 ID），处理器忽略负载中的 `userId`。 |
| 严重 | 非对局玩家可对任意对局提交 `SURRENDER` 等操作（网关与引擎均未校验成员身份）。 | 已修复：网关校验 `session.playerIds`，引擎 `dispatchAction` 拒绝非本局玩家。 |
| 严重 | 未登录游客的 ID 固定为 `'guest'` / `'guest_lobby'`，大厅建房的房主为占位 `'host'`：所有游客被识别为同一人，游客之间无法正常对战，且建房后会出现「幽灵房主」占位。 | 已修复：每个浏览器生成唯一游客 ID（兼容迁移旧值）；房间改由房主通过 Socket 首次加入时创建。 |
| 严重 | 房间密码从未校验，「密码房」任何人都能进入。 | 已修复：服务端校验密码摘要；前端新增密码输入弹窗；密码不再出现在 URL 中。 |
| 严重 | 房间关闭后重新开启时从仓储恢复，`hasPassword` 为真但不再校验密码；仓储中保存的是明文密码。 | 已修复：恢复时同步密码摘要、已关闭房间按新房间处理、仓储只存摘要。 |
| 严重 | `room:ready` 携带的自定义卡组以 `isValid=true` 直接写入，且可通过 `customDeck.id` 覆盖系统预组或他人卡组（任何人可篡改所有玩家使用的官方预组）；卡组也不经过 5.1 构筑校验。 | 已修复：系统预组只读；自定义卡组必须通过 `validateDeck`，且只写入本人名下。 |
| 严重 | `DELETE/PUT /api/decks/:id`、`POST /api/decks` 可无鉴权删除或改写系统预组。 | 已修复：系统预组与他人卡组返回 403。 |
| 高 | 默认 JWT 密钥与默认管理员密码 `admin888` 写死在源码中，任何部署都可伪造管理员令牌。 | 已修复：未配置 `JWT_SECRET` 时随机生成；生产环境未配置 `ADMIN_PASSWORD` 时随机生成并打印；演示账号仅非生产环境预置；JWT 增加 7 天有效期。 |
| 高 | 密码以固定盐 HMAC-SHA256 存储。 | 已修复：scrypt + 随机盐，登录时自动升级旧摘要。 |
| 高 | `game:action` 处理器无异常兜底，引擎抛错会成为未处理的 Promise 拒绝，可能使进程崩溃。 | 已修复：所有处理器 `try/catch` 并以 `game:error` 回报。 |
| 中 | `/api/admin/monitor` 无需鉴权。 | 已修复：仅管理员；监控页与压测脚本改为携带管理员令牌。 |
| 中 | 非房间成员发送 `room:leave`（如访客离开页面）会重置房间内所有人的准备状态。 | 已修复：非成员离开请求不影响房间。 |
| 中 | 分页参数 `take` / `limit` 无上限。 | 已修复：限制在 1~1000 / 1~200。 |
| 中 | `game:choice` 未做限流；同一账号多标签页时，关闭其中一个即被判为掉线。 | 已修复。 |
| 建议 | 服务端固定使用内存仓储，重启后账号、卡组、对局记录全部丢失；`docker-compose` 中的 PostgreSQL 与 Prisma 仓储未接入。README 原称「开箱即用 SQLite」与实际不符（已更正文案）。 | 建议在 `DATABASE_URL` 存在时切换到 `Prisma*Repository`。 |
| 建议 | `POST /api/rooms`、`POST /api/decks` 仍接受客户端自报的 `creatorId` / `userId`。前端已不再使用前者。 | 建议改为从 JWT 获取身份，游客卡组仅存本地。 |
| 建议 | CORS 对所有来源放行。认证使用 Bearer 令牌而非 Cookie，风险较低，但 `CORS_ORIGIN` 配置项实际未生效。 | 建议明确是否需要该配置，避免误导。 |

## 三、样式与可访问性

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| 高 | `w-26`、`h-22`、`rounded-xs`、`shadow-xs`、`py-0.2` 在 Tailwind v3 中不存在。`CardView` 中号卡牌使用 `w-26 sm:w-28`，手机宽度 (<640px) 下卡牌没有宽度。 | 已修复：在 `tailwind.config.ts` 扩展尺寸，`py-0.2` 替换为 `py-px`。 |
| 中 | 26 处 `animate-in` / `fade-in` / `zoom-in-95` / `slide-in-*` 依赖未安装的 `tailwindcss-animate`，所有弹窗入场动画均未生效。 | 已修复：安装并启用插件。 |
| 中 | 全局 `user-select: none` 会导致 iOS Safari 输入框无法聚焦/选中。 | 已修复：表单控件单独放开。 |
| 中 | 字体栈不含中文字体，Windows 下中文回退效果不稳定。 | 已修复：加入苹方 / 微软雅黑 / 思源黑体。 |
| 中 | 无键盘焦点样式；大量持续闪烁/弹跳动画未考虑 `prefers-reduced-motion`；图标按钮没有 `aria-label`。 | 已修复：全局 `:focus-visible`、减少动态效果媒体查询、主要图标按钮与弹窗补充 ARIA。 |
| 建议 | 规则手册与新手指南直接引用第三方 MinIO 域名上的图片，外部域名不可用时页面图片全部失效。 | 建议将这些图片放入本地 `public/`。 |

## 四、性能

| --- | --- | --- |
| 严重 | 原图 PNG 平均约 2 MB（最大 8 MB），对局内费用区、墓地、处理区、悬停浮窗、效果选择弹窗，以及管理后台列表、卡组封面都直接加载原图，一局对战可下载数十 MB。现有缩略图仅约 45 KB（约 1/40）。 | 已修复：上述 40~200px 级别的展示全部改用缩略图并回退原图（已核对 805 张卡图均有缩略图）。 |
| 高 | 对局页在 `window.mousemove` 上对整张 1800 行页面组件 `setState`，鼠标每移动一次就重渲染整个桌面（`CardView` 的 `React.memo` 因内联回调而失效）。 | 已修复：光标跟踪收敛到悬浮窗组件内部，仅在悬停时监听并用 `requestAnimationFrame` 节流。 |
| 低 | 对局页每次渲染都 `console.log`。 | 已修复。 |
| 低 | 监控页在后台标签页也每 1.5 秒轮询。 | 已修复。 |
| 建议 | `src/lib/cards-data.ts`（约 2 万行卡牌数据）被打进客户端包，对局页首屏 JS 约 200 KB。 | 建议改为按需加载的 JSON 或由服务端接口提供。 |
