# 规则引擎内核审查报告 (2026-10)

审查范围：`packages/game-engine`（`engine.ts`、`phases/`、`combat/`、`zone/`、`sba/`、`priority/`、`state/`、`effects/card-effects.ts`），以及服务端下发事件时与引擎相关的部分。
审查基线：`f2f9cce`（main）。规则依据：官方《综合规则》V1.4 与规则 Q&A 第 1~10 期（见 `docs/rules/rule-specification.md`）。
现有测试：引擎 58 个用例全部通过，但其中一部分用例断言的是**错误行为**（见第五节），需要随修复一起改写。

级别说明：**严重** = 可被利用作弊、泄露隐藏信息或导致对局状态损坏；**高** = 核心规则错误，正常对局中经常出现；**中** = 规则偏差，特定卡牌或局面下出现；**低** = 代码质量或遗留代码。

## 一、安全与对局状态完整性

| 级别 | 问题 | 位置 |
| --- | --- | --- |
| 严重 | **玩家决策的提交内容完全不校验**：`handleChoiceResolution` 不检查 `selectedIds` 是否属于该决策的选项、是否可选 (`eligible`)、数量是否在 `minSelections`~`maxSelections` 之间。例如「破坏对方 1 张 PP 8000 及以下的角色」可以提交任意卡牌 ID、提交多张，直接破坏对方任意角色；「从墓地出场」可以提交牌组或对方的卡牌。 | `effects/card-effects.ts` `handleChoiceResolution` |
| 严重 | **`EQUIP_ITEM` 不校验装备牌**：不检查阶段、回合玩家、卡牌归属、卡牌类型、所在区域。可以把对方手牌、牌组中的任意卡牌 ID 当作「装备」放到自己角色下方。 | `engine.ts` `EQUIP_ITEM`、`battlefield-manager.ts` `equipToRole` |
| 严重 | **`ELIMINATE_3_ORBS` 不校验阶段与回合玩家**，并且允许「同色但不相邻」的三消（规则要求相邻、不要求同色，4.16.2 / 6.4.1.b.5），也允许消除信号球区中不带信号球标记的牌。 | `zone-manager.ts` `eliminateThreeOrbs` |
| 严重 | **卡牌实例 ID 泄露隐藏信息**：ID 为 `inst-<玩家>-<序号>`，序号按卡组列表顺序分配。官方预组的卡表是公开的，而 `CARDS_DRAWN`、`CARD_MOVED` 等事件会广播给双方，对手据此可以推算出抽到的、调度的、放进暗费的是哪张牌。 | `state/create-game.ts` |
| 严重 | **行动失败时状态不回滚**：`dispatchAction` 没有事务。多处在支付费用之后才做合法性检查（卡位不足、战术牌使用条件、装备失败、横置代价），失败时返回错误，但费用已经支付、卡牌可能已进入处理区。 | `engine.ts` `handlePlayCard` / `handleActivateAbility`、`card-effects.ts` `handlePlayTactics` |
| 严重 | **有待决策时仍可执行其他行动**：存在 `currentPendingChoice` 时，玩家仍能出牌、攻击、结束回合；新的决策会直接覆盖旧的决策（只有一个决策槽），旧决策对应的效果丢失。 | `engine.ts` `dispatchAction` |
| 高 | 攻击者、攻击对象、阻挡者只检查「在战场」，不检查是否是卡位上的**角色**。辅助机、单独占位的装备、角色装备中的装备牌、升变后垫在下方的牌（`zone` 仍为 `BATTLEFIELD`）都可以被选为攻击者、阻挡者或攻击对象。 | `combat/combat-manager.ts` |
| 高 | 回合外玩家可以在对方的自由时点发动【起】能力（规则只允许在自己回合的主要阶段，8.1.1.c / 6.4.1.b.3）。 | `engine.ts` `handleActivateAbility` |

## 二、流程与时机（架构问题）

| 级别 | 问题 |
| --- | --- |
| 高 | **流程不能挂起等待玩家决策**。引擎是同步执行的：攻击充能、伤害充能、战斗步骤中一旦需要玩家选择（如【充能自】二选一），引擎只是设置 `currentPendingChoice` 然后**继续执行**到攻击结束。结果：攻击充能翻出红色信号球选择「DP+1」时，伤害步骤早已结算完毕，DP+1 不会作用于本次攻击；充能数为 2 或伤害为 2 时，第二个决策覆盖第一个，第一个效果丢失。 |
| 高 | **自动能力从不执行**：`CheckTimingManager.executeTriggerAbility` 是空函数，`pendingTriggers` 从未被写入。所有【自】、「攻击时」「回合结束时」「被破坏时」等触发都没有实现，个别卡牌在其他位置做了硬编码。 |
| 高 | **没有【瞬时】时点**：自由时点步骤中没有轮流使用瞬时的窗口，回合外玩家只能直接选择阻挡；结束阶段没有瞬时窗口 (6.5.1.a)。`USE_INSTANT` 在协议类型中存在，但引擎与前端都没有实现，所有瞬时战术牌和【瞬时】能力都无法在规则时点使用。协战机制 (8.13) 也因此无从实现。 |
| 中 | 结束阶段超出手牌上限时自动弃掉最后几张，玩家无法选择 (6.5.1.c)；`DISCARD_HAND_OVERFLOW` 同样未实现。 |
| 中 | 竖直阶段没有「回合开始时」触发、冰冻、浮空回场；伤害充能后没有逐次进入检查时机 (4.12.3.b)。 |
| 中 | 持续效果没有期限模型：所有临时加成都存在 `tempPPBonus` / `tempDPBonus` / `grantedKeywords` 中，在**每个**结束阶段一律清空。「直到下个回合结束为止」的效果（暗域力场、露娜·银冕 BP01-008 等）在当回合结束就消失；8.9.2（不作用于之后进入的卡牌）也无法表达。 |
| 中 | 不存在永久能力的持续计算：PP/DP 只计算基本值 + 装备 + 临时加成，所有「【永】：……PP+1000」「【永】：【速攻】」之类的能力只能靠关键字匹配（见第四节）或完全不生效。 |

## 三、区域、状态与核心规则

| 级别 | 问题 | 规则 |
| --- | --- | --- |
| 高 | **区域内顺序依赖 `state.cards` 对象的键插入顺序**。`moveCard` 不调整顺序，所以信号球区、墓地的「最上方」实际上是卡牌实例创建时的顺序，而不是放入的先后。三消的相邻判定、暮/晖形态参照的「最下方」都会出错。 | 3.7.2、4.16.2、10.14 |
| 高 | **牌组更新后没有洗切**：`this.rng.shuffle(gyCardIds)` 的返回值被丢弃，墓地以原顺序成为新牌组。 | 9.2.2 |
| 高 | 卡牌离开区域后不重置状态：`grantedKeywords`、`tempPPBonus`、`tempDPBonus`、`slotIndex`、`attachedEquipmentId` 在卡牌回到手牌、墓地后仍保留。升变获得的【速攻】在卡牌回手后再次打出时依然有效。 | 3.1.4 |
| 高 | 费用统计 (`openCostCount`、`availableOpenCostCount`、`hiddenCostCount`、`totalCostCount`) 以手工增减维护，与费用区实际卡牌不同步。所有通过效果移动费用区卡牌的路径都没有更新统计，进而影响支付判定和费用区上限判定。 | 3.6 |
| 高 | 升变：限制条件（「费用上限 X 及以上」）**从不检查**；「X以下」按「≤」处理（官方 10.12 规定为「<」）；升变对象以「名称包含」匹配，不区分特征 `<>` 与卡名 `《》`，导致 `<阿尔法>` 等以特征为对象的升变无法使用；只要卡牌文本中出现「速攻」就赋予【速攻】（BP03-003 等升变能力不给速攻的卡也会获得）；只要指定的卡位有角色就自动改为升变。 | 8.11、10.12 |
| 高 | 关键字判定基于整段文本包含：卡牌文本中只要出现「贯通」「同命」就视为持有该能力（如 BP01-010「使露娜·银冕获得【贯通】」会让自己获得贯通；BP04-056 条件获得的同命被视为永久持有）。 | 10.7、10.16 |
| 高 | 【同命】实现错误：被攻击方持有同命时会带走攻击者（规则只在持有者自己攻击结束时、可选地发动）；攻击方 PP 较低时被强制发动。 | 10.16 |
| 高 | 攻击充能中翻出的**非信号球**卡牌的【充能自】不处理（BP03-023/028/032、PR-030 等）；信号球在处理【充能自】之前就已放入信号球区。 | 4.12.2、10.2 |
| 中 | 支付费用时由引擎自动先横置明费、后使用暗费，玩家不能选择。暗费回合结束会送墓，自动优先用明费会让玩家吃亏；而部分卡牌依赖「支付过暗费」(BP03-015)。 | 3.6.5.a |
| 中 | 战场上的辅助机：未指定卡位时回退到 0 号卡位，可能与角色叠放在同一卡位。 | 8.6.2.b.2 |
| 中 | 调度没有强制先攻玩家先进行。 | 5.2.1.e |
| 低 | `GameEngine` 构造函数默认 `skipMulligan: true`、默认使用 `BASE_TEST_CARDS`；`fromSnapshot` 未传卡表时也回退到测试卡表。两种后端目前都正确传入了参数，但默认值容易误用。 | AGENTS.md |

## 四、卡牌效果层 (`card-effects.ts`)

整体结论：**除少数卡牌外，卡牌效果是近似实现，不能作为规则依据。**

1. **7 个硬编码分支对应了错误的卡牌**（代码中的卡名来自早期的占位卡表，与现行卡表不一致）：

   | 卡号 | 代码以为是 | 实际卡牌 | 后果 |
   | --- | --- | --- | --- |
   | BP01-003（第二分支） | 丽芙·蚀暗「查看牌组顶 3 张取道具」 | 露西亚·鸦羽 | 第一分支不满足时会执行错误的检索 |
   | BP01-004（起动） | 里·异火「造成 1000 点效果伤害」 | 露西亚·鸦羽 | 该卡没有【起】，分支不可达；测试断言了这一不存在的效果 |
   | BP01-008（出场） | 「将对方角色横置放到对方费用区」 | 露娜·银冕 | **出场时会把对方角色送进费用区** |
   | BP01-010（起动） | 露娜·银冕「换费用」 | 罗兰·戏炎 | 不可达 |
   | BP01-011（出场） | 露娜·银冕「墓地复活」 | 冕饵（装备） | 不可达 |
   | BP01-012 | 闪避充能 | 沃托（辅助机） | 不可达 |
   | BP01-013 | 超算空间「抽 2 张」 | 终焉降临 | **使用时抽 2 张**，真实效果（侵蚀 -1）不执行 |

   另有 `engine.ts` 中 BP01-016 的减费：代码写的是「战场有露西亚或阿尔法时费用 -3」，现行卡表 BP01-016 没有这个能力（这是 BP01-002 的变体文本），导致 BP01-016 错误地减费。
2. **分支以文本片段匹配且不 `return`，会串到其他卡牌上**：例如以「消除2同色信号球」识别 ST03-001 的分支，会对 BP01-001/002/010/073、BP02-021、ST03-001 等所有包含该片段的卡生效；它不询问是否支付代价，直接移走前两张信号球（不论颜色、是否相邻），竖直自身而不是所选的<三头犬小队>角色，并给**所有**友方角色 PP+2000。BP01-002 则不支付代价直接获得【突进】，且不获得【充能0】。
3. **代价普遍不支付**：苦刑之女的「消除【任意信号球】」、露娜·银冕 ST02-001 的「消除【2蓝色信号球】」等起动能力代价未支付；「可以」的可选效果被强制执行。
4. **通用解析器按关键字执行**：`resolveUniversal*` 只要在文本中找到「抽X张牌」「侵蚀计数-1」「破坏」「PP-X」等片段就执行，忽略条件、对象、代价、「若如此做」，也会把条件分支中的效果一并执行。
5. 预组卡的具体偏差（节选）：
   - ST01-002 里·异火：【充能+1】被实现为 PP+1000；「可以」放置到墓地被强制执行。
   - ST02-001 露娜·银冕：墓地复活不限<升格者>，且不支付代价；【永】侵蚀 5 以上<升格者> PP+1000 未实现。
   - ST02-010 刹那制裁：侵蚀为 0 时按 1 计算 (`Math.max(1, erosion)`)。
   - ST03-010 暗域力场：作用于所有横置角色而非<三头犬小队>，且在当回合结束就消失（应持续到下个回合结束，这张卡的作用就是在对方回合防守）。
   - ST01-011 重逢、ST03-011 三头犬出击：没有合法对象时拒绝使用（规则上可以使用，效果不执行，8.6.3.a.3）。
6. 遗留的「Mock 模式」分支（「3张以上明费 PP+500」「比安卡·零度」「卡列尼娜·爆裂 攻击宣言时」「红莲狂士」「辅助机·凌鹤」）对应的卡牌在现行卡表中不存在，应删除。

## 六、整改计划

按「每个 PR 可独立评审、独立回滚、合并后自建部署仍可用」拆分：

1. **PR：安全与完整性加固**（不改协议）
   - 决策提交校验（选项归属、可选性、数量）；有待决策时只接受该决策与弃权。
   - `dispatchAction` 事务化：失败时回滚状态、随机数与事件。
   - `EQUIP_ITEM`、`ELIMINATE_3_ORBS`、`ACTIVATE_ABILITY` 的阶段、回合玩家、归属、卡牌类型校验；三消只允许相邻信号球。
   - 攻击者、攻击对象、阻挡者限定为卡位上的角色。
   - 卡牌实例 ID 随机化（由对局种子派生，保证可重放）。
2. **PR：区域与状态模型修正**（不改协议）
   - 区域内顺序：移动卡牌时调整其在 `state.cards` 中的位置，使「最后放入 = 最上方」在所有区域成立；牌组更新正确洗切。
   - 卡牌移动时按 3.1.4 重置区域相关状态；下方的牌与装备不再被视为战场上的独立卡牌。
   - 费用统计改为从费用区实际卡牌派生。
   - 升变的限制条件、「以下」严格比较、特征/卡名对象、升变能力赋予的关键字。
   - 关键字（速攻、突进、贯通、同命、充能X）只从对应能力中识别，并修正同命、贯通、非信号球【充能自】。
   - 删除错位的硬编码分支与遗留 Mock 分支，改写第五节列出的测试。
3. **PR：流程挂起/恢复与时机窗口**（需要前端配合，两种部署都要实际打一局）
   - 把战斗、充能、结束阶段改为可挂起的步骤队列：需要玩家决策时暂停，提交后从原位置继续；支持多个待处理决策排队。
   - 实现自由时点与结束阶段的瞬时轮流窗口 (`USE_INSTANT`)、结束阶段弃牌选择 (`DISCARD_HAND_OVERFLOW`)、自动能力的待机与检查时机处理。
   - 前端对接新的时机窗口。
4. **PR 系列：卡牌效果重写**
   - 为卡牌效果建立声明式描述（代价、条件、对象、效果、期限），持续效果按 8.9 分层计算。
   - 先完整、精确地实现三套官方预组（ST01~ST03）并逐卡写测试，再按卡包推进。
   - 在全部实现前，对未精确实现的卡牌给出明确提示，而不是按关键字近似执行。
